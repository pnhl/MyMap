# Reviewed native locks

Google/Fire app lockfiles and SHA-256 verification metadata are captured from credential-free CNG + native Kotlin/JVM test builds on Windows. Both compile paths also run with strict verification. AAPT2 detached configuration was resolved by actual compilation; pinned Linux/macOS/Windows classifier hashes were downloaded from official Google Maven (origins in tool-origins.json). Production never accepts new checksums automatically. These files do not prove full signed/R8 builds on every host. Podfile.lock is still BLOCKED until resolved on matching macOS; no fabricated Pod lock is supplied.

On a clean fixture checkout with no credentials, run CNG. iOS: `cd ios && pod install`, then `node scripts/native-locks.cjs capture ios`. Android for each store: `./gradlew :app:dependencies --write-locks --write-verification-metadata sha256`, then `node scripts/native-locks.cjs capture android play` (or amazon). Review repository origins, all transitive checksums and both flavor lock entries; commit the resulting files. Regenerate after any native dependency/plugin change. Never copy signing/Firebase inputs into this folder.

Production CI and native fixture CI restore reviewed locks after CNG, use strict Gradle verification, and iOS uses `pod install --deployment`. Source pins/repositories were reviewed for the exercised paths; initial checksums are trust at capture, not publisher signatures. Review any new coordinate/checksum against upstream before committing. Fire unsigned Release R8 (arm64-v8a) and Wear compile also pass strict verification on Windows. Google full release, other ABIs/hosts and CocoaPods remain unverified; this is not a completed five-artifact reproducibility claim.
